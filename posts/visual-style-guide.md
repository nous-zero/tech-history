# tech-history 콘텐츠 시각화 톤앤매너 가이드

> 목적: 글마다 이미지 스타일이 달라서 생기는 조잡함을 없애고,
> 이미지만 봐도 "이 시리즈 것"임을 알게 한다. 모든 발행 이미지는 이 가이드를 따른다.

## 1. 색 — 4색 이내로 고정

| 역할 | 색 | 용도 |
|---|---|---|
| 기본 | 먹색/회색 계열 | 노드·선·본문 글자 |
| 강조 | 파랑(청색) 1색 | 핵심 경로·주인공 기술 |
| 위험 | 빨강 1색 | 끊김·장애·문제 지점 (✕ 표시와 함께) |
| 배경 | 흰색(라이트)/진회색(다크) | 무늬·그라데이션 금지 |

- 한 이미지에 의미 있는 색은 최대 2개(강조+위험). 색이 3개 이상 필요하면 그림을 2장으로 쪼갠다.

## 2. 형태 — 어휘를 통일한다

- 장치/거점 = **원**, 연결 = **직선**, 데이터 조각 = **작은 사각형**
- 끊김/고장 = 빨간 **점선** + **✕**
- 강조 경로 = 파란 **굵은 선**
- 그림자·입체·그라데이션·클립아트 금지. 전부 평면(플랫).

## 3. 구도 — 두 가지 틀만 쓴다

1. **좌우 비교**: 문제(왼쪽) vs 해결(오른쪽) — 예: 별 모양 전화망 vs 그물망
2. **타임라인**: 연도 → 사건 흐름 (가로 1줄)

## 4. 글자

- 고딕 계열 1종. 제목(굵게) / 라벨 / 캡션(작게) 3단계만.
- 캡션은 이미지 하단 1~2줄: "무엇이 어떻게 된다"를 완결 문장으로.
- 이미지 우하단에 시리즈 서명 고정: `tech-history 01` (편 번호).

## 5. 비유 실명(實名) 태그 — 글·이미지 공통 원칙

비유를 쓰면 반드시 그 자리에서 실제 명칭을 붙인다.
- 예: "교차로마다 우체국을 세운다 — 이 우체국의 실제 이름은 IMP, 오늘날의 라우터다."
- 이미지 라벨도 동일: `우체국(라우터)` 처럼 비유(실명) 병기.
- 독자가 "이거 실화인가 비유인가" 헷갈리는 순간 신뢰가 깨진다. 비유는 이름에만 허용하고, 동작 설명은 사실만 쓴다.

## 6. 대화체 각색 표기

- 실존 인물에게 지어낸 대사를 직접 귀속하지 않는다(무명 배역: 장군·참모·연구원).
- 대화 장면 첫머리 또는 글 끝에 "대화는 이해를 돕기 위한 각색입니다" 1회 명시.

## 7. 실제 사례 연결 원칙

역사 속 문제가 **지금도 살아있음을 보여주는 현대 사례**를 1편당 1개 넣는다.
- 예: 그물망의 고립 위험 → 2022년 통가 해저케이블 단절로 국가 전체 고립.
- 선정 기준: ①언론 보도·공식 기록으로 검증 가능할 것 ②독자의 '지금'과 연결될 것(내 폰, 내 회사, 뉴스에서 본 것) ③1편당 1개만(많으면 산만).
- 사례도 출처 표기 대상이다(작성 원칙 1과 동일).

## 8. 게시물 도입·마무리 프레임 (첫 방문자 기준)

처음 보는 방문자도 "무슨 시리즈의 몇 편인지" 3초 안에 알게 한다(2026-07-24 1편 게시 후 피드백).
- 1행: 간판 라벨 `[테크스토리 #NN | 기술키워드 — 구체적 사건/숫자 제목]` — 링크드인은 첫 2~3줄만 보이므로 라벨+후킹 문장이 최상단.
  제목 규칙(2026-07-24 피드백): ①기술 고유명사(ARPANET, TCP/IP, React 등) 필수 — 검색·SEO에 걸리는 단어 ②구체적 사건·숫자로 클릭 유도 ③"인터넷의 시작" 같은 두리뭉실 추상 제목 금지. 예: "[테크스토리 #09 | npm left-pad 사태 — 11줄이 지워지자 페이스북이 멈췄다]"
- 2행: 후킹 문장(장면·반전).
- 3~4행: 시리즈 소개 1~2문장(누가·왜) — 1편은 자기소개 포함, 2편부터는 한 줄 + 전편 언급.
- 마무리: `다음 편(#NN): 예고` + 발행 주기("3일에 한 편씩").

## 9. 제작 파이프라인

1. 글 초안에서 "독자가 막힐 지점"을 고른다 (질문이 나올 곳 = 그림이 필요한 곳). 낯선 용어가 처음 나오는 자리에는 용어 이해용 이미지를 배치한다.
2. 각 시리즈 폴더의 생성 스크립트(예: [frontend/images/generate_images.py](./frontend/images/generate_images.py))에 함수를 추가해 PNG(1200x630)를 직접 생성 — 색·글꼴·서명이 코드로 고정되어 톤앤매너가 자동 유지되고, 변환·별도 관리가 필요 없다. 새 시리즈(백엔드 등)를 시작하면 `posts/<시리즈명>/` 폴더를 만들고 이 스크립트의 공통 도우미(색·헬퍼 함수)를 복사해 시작한다.
3. 검수: 생성된 PNG를 실제로 열어 눈으로 확인(글자 깨짐·라벨 정렬·겹침). 한글 글꼴에 없는 특수문자(✕ 등)는 쓰지 않는다 — □로 깨진 전례 있음(2026-07-24).
4. 발행 글에는 마크다운으로 이미지를 인라인 삽입(`![설명](./images/파일.png)`)해 문서에서 바로 보이게 한다. 1편당 이미지 2~3장.
