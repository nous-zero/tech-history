# 본편 BGM 도입 제안서 (집행 보류 — 사용자 승인 대기)

작성: audio-producer, 2026-07-29
지시: coordinator — "BGM은 이번 편에서 집행하지 마라. 별도 제안서로 남겨라."
상태: **미집행**. 소재 조달·법무 심사가 필요한 신규 범위이며, 본 문서는 승인 판단용 근거만 제공한다.

## 0. 왜 이 제안이 나왔나 (실측 근거)

사용자 청음 피드백은 "쇼츠는 음질이 좋은데 본편은 안 좋다"였다. 속도 요인은 무음 다듬기로 처리했고
(refs/audio-qc-ep03.md 참조), 그 과정에서 **본편에 BGM이 아예 없다**는 사실이 코드 실측으로 확인됐다.

| 근거 | 실측 |
|---|---|
| 본편 조립기에 BGM 코드 존재 여부 | `video/build_v2.py` 에 `bgm`·`BGM`·`loudnorm`·`apply_gain` 문자열 **0건** (grep) |
| 쇼츠 조립기 | `video/build_shorts.py:102` `def make_bgm(...)` — 주석 원문이 **"무음 제거용, 낮게 깔림"** |
| 쇼츠 믹싱 | `build_shorts.py:1284-1285` BGM 을 `apply_gain(-13)` 후 내레이션을 그 위에 overlay |
| 산출물 | `03_v2/shorts_A_bgm.wav` 존재 / `episode_bgm.wav` **부재** |

즉 쇼츠는 문장 사이 공백을 음악이 메우고, 본편은 맨 목소리만 남는다. 코드 주석이 그 목적을 명시하고 있다.
**추정(확인 필요)**: 사용자가 느낀 "음질" 차이의 상당 부분이 이 차이일 가능성 — 다만 사람 청음 검증은
에이전트가 할 수 없으므로 단정하지 않는다.

## 1. 무료·상업이용 가능 음원 후보 경로

판단 기준은 refs/free-media-sources.md 3절이며, 아래는 그 원문 대조 결과다.

| 후보 | 상업 이용 | 표기 | 전 플랫폼(크로스포스팅) | 판정 |
|---|---|---|---|---|
| **ACE-Step 자체 생성** (MIT) | 예 | 불요 | 예 | **1순위** — 라이선스 리스크 0, 편별 맞춤 작곡 가능. 단 GPU 필요(코랩/캐글) |
| **Pixabay Music** | 예 | 불요 | **예** | **2순위** — KB가 "기본값"으로 지정. 음원 단독 재배포만 금지 |
| Mixkit Music | 예 | 불요 | 유튜브·SNS·팟캐스트 OK / 방송·게임 불가 | 3순위 (현 채널 범위에선 문제 없음) |

| **YouTube Audio Library** | 유튜브 수익화 OK | CC-BY 트랙만 | **아니오** | ⚠️ **비권장 — 아래 경고 참조** |

### ⚠️ 경고: 유튜브 오디오 라이브러리는 채택하면 안 된다

coordinator 지시문에 후보로 적혀 있었으나, 프로젝트 지식 베이스와 **정면 충돌**한다.
refs/free-media-sources.md 3절 원문: 유튜브 오디오 라이브러리는 "유튜브 한정으로 보는 게 안전 —
틱톡·릴스·팟캐스트 재사용 비권장". 같은 절의 핵심 규칙은 플랫폼 라이브러리 음원의 권리가
"그 플랫폼 안에서만 유효 — 크로스포스팅 시 무단 사용이 됨"이라고 못박고 있다.

이 프로젝트는 channel-adapter 에이전트가 **같은 영상을 틱톡·인스타그램·링크드인으로 각색 배포**하는
구조다. 유튜브 라이브러리 음원을 구워 넣으면 유튜브 밖 배포분이 전부 무단 사용이 된다.
→ **채택 불가.** KB가 제시한 해법(같은 절)은 "소스에서 라이선스가 나오는 음악(Pixabay·Mixkit·CC-BY·
자체 생성 ACE-Step)을 영상에 구워 넣어 전 플랫폼 동일 파일 배포"다. 본 제안서는 그 해법을 따른다.

*(이 항목은 copyright-counsel 최종 판정 대상 — audio-producer 단독 판단으로 확정하지 않는다.)*

**2026-07-29 coordinator 승인**: 이 경고는 타당한 것으로 인정되어 유튜브 오디오 라이브러리는 후보에서
제외 확정, ACE-Step(1순위)·Pixabay(2순위) 구도 유지. 판정은 `refs/free-media-sources.md` 3절에
교차 참조로 박제됨(4편 착수 시 재조사 불요).

## 2. 본편 BGM 볼륨 기준 (실측 근거)

쇼츠에서 이미 검증된 비율을 그대로 쓰는 것이 안전하다. 실측값:

| 대상 | Integrated LUFS | 비고 |
|---|---|---|
| `shorts_A_bgm.wav` (생성 원본) | **-29.1** | ffmpeg loudnorm 측정 |
| 믹스 시 적용 게인 | **-13 dB** | `build_shorts.py:1284` |
| → 믹스 안의 BGM 실효 레벨 | **약 -42.1 LUFS** | -29.1 + (-13) |
| `shorts_A_audio.wav` (최종 믹스) | **-22.8** | 내레이션이 지배 |
| **내레이션 대비 BGM** | **약 -19 LU** | -42.1 vs -22.8 |

**권장 기준: 내레이션 대비 -19 LU (허용 범위 -18 ~ -22 LU).**
coordinator가 제시한 -18~-22dB 범위와 실측이 일치한다 — 추정이 아니라 현행 쇼츠에서 뽑은 수치다.

추가 요건:
- **덕킹(ducking, 음성이 나올 때 음악을 자동으로 낮추는 것)**: 무음 다듬기로 문장 사이가 0.40초 상한까지
  줄었으므로, 반응이 느린 덕킹은 오히려 펌핑(음악이 들썩이는 현상)을 만든다. 정적 -19 LU 고정을
  먼저 시도하고, 필요 시에만 `sidechaincompress` 검토 권장.
- 본편은 라우드니스 정규화를 이미 적용했으므로, **BGM 은 정규화 이전 단계에서 믹스**해야 최종 LUFS 가 맞는다.
  (지금 순서로 BGM 을 나중에 얹으면 목표 LUFS 를 초과한다.)

## 3. 1~3편 소급 적용 시 재렌더 비용

| 항목 | 실측 |
|---|---|
| 본편 1편 렌더 소요 | **약 26분** (`03_v2/_render_body.log` 진행 타이머 최대 25:58 관측) |
| 로컬 CPU | 2코어 — 병렬 렌더 불가, 순차 처리 전제 |
| 3편 소급 시 | 본편 3회 ≈ **약 78분** + 쇼츠 재렌더 별도 |

단, BGM 만을 위한 재렌더는 **불필요할 수 있다**: BGM 은 오디오 트랙에만 얹히므로
영상 트랙을 다시 만들지 않고 `ffmpeg` 재먹싱(remux — 영상은 그대로 두고 소리만 갈아끼우기)으로
처리 가능하다. 이 경로면 편당 **1분 미만**. **확인 필요** — `build_v2.py` 의 먹싱 단계(2214행 부근)를
재사용할 수 있는지 video-producer 검토 필요.

## 4. 권장안

1. **음원**: ACE-Step 자체 생성(MIT) 1순위, 조달 실패 시 Pixabay Music. 유튜브 오디오 라이브러리 **제외**.
2. **레벨**: 내레이션 대비 -19 LU 고정, 덕킹은 보류(펌핑 위험).
3. **적용 범위**: **4편부터 신규 적용**을 기본으로 하고, 1~3편 소급은 재먹싱 경로가 확인되면 저비용이므로
   그때 재검토. 소급을 위해 본편을 통째로 재렌더하는 것은 비용 대비 이득이 불명확.
4. **선행 조건**: ① copyright-counsel 라이선스 최종 판정 ② asset-ledger.md 등록(현재 BGM 등록 건수 **0건**
   — grep 실측) ③ 사용자 1회 청음 승인(에이전트는 청취 불가).
