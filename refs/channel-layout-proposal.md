## 권고 요약 3줄

1. **본편 전용 재생목록 1개를 만들고 쇼츠는 넣지 마라.** 우리 시리즈는 1→2→3 순서가 내용의 일부인데, 유튜브 공식 문서상 **쇼츠만 든 재생목록은 순서 변경이 불가**하고 쇼츠+본편 혼합 재생목록의 실제 재생 동작(세로 플레이어로 열리는지·연속재생이 이어지는지)은 **공식 문서에서 확인되지 않았다**. 순서가 생명인 콘텐츠에 동작이 불확실한 구조를 넣지 않는다.
2. **채널 홈은 "본편 시리즈 → 쇼츠 → 최근 업로드" 3줄로 고정한다.** 현재 커스텀 섹션은 **0개**(실측). 유입의 96.6%가 쇼츠 피드에서 오므로, 채널에 들어온 쇼츠 시청자에게 **가장 먼저 보여야 할 것은 본편 시리즈**다. 쇼츠는 이미 아는 것이니 두 번째 줄로 내린다.
3. **추가 인증 없이 지금 있는 업로더 토큰으로 재생목록 생성·편입이 된다.** 업로드 스크립트에 `--playlist` 옵션이 이미 있다(실측). 4편부터는 업로드와 동시에 자동 편입한다.

## 2. 재생목록 설계안

### 2-1. 편성 구조 — 본편과 쇼츠를 분리한다

| 목록 | 담을 것 | 순서 | 공개 |
|---|---|---|---|
| **A. 본편 시리즈** | 본편 3편 (4편부터 계속 추가) | 1편 → 2편 → 3편 (발행 순 = 이야기 순) | 공개 |
| **B. 쇼츠 모음** | 쇼츠 6편 | 편 순서(1A·1B·2A·2B·3A·3B) | 공개 |

**왜 섞지 않는가 (근거)**
- 유튜브 공식 도움말: **"Shorts만 들어 있는 재생목록은 순서 변경(reorder)이 불가"** (support.google.com/youtube/answer/57792, 2026-07-30 확인). 쇼츠가 순서 제어에서 예외 취급을 받는다는 증거다.
- 혼합 재생목록의 실제 재생 동작(쇼츠 항목에서 세로 플레이어로 튕기는지, 연속재생이 끊기는지)은 **공식 문서·신뢰 출처 모두에서 확인되지 않았다**. 확인된 것은 `/shorts/{id}` URL이 세로 플레이어로 강제된다는 것뿐.
- 우리 시리즈는 **"문제 → 해결 → 새로운 문제"가 편을 넘어 이어지는 구조**다. 3분짜리 본편 사이에 40초 요약 쇼츠가 끼면 같은 내용을 두 번 보게 되어 이탈 사유가 된다.
- → **rule6(측정 우선)**: "섞으면 안 된다"고 단정하지 않는다. 결재 항목 (마)로 **임시 재생목록을 만들어 실제 동작을 1회 측정**한 뒤, 측정 결과가 문제없으면 통합안을 재검토한다.

### 2-2. 제목·설명 (rule8 SEO — 앞부분 키워드 배치)

재생목록 제목은 **150자 한도지만 피드에서는 50~70자에서 잘린다**([추정] — 2차 출처 다수 일치, 유튜브 공식 수치 미확인). 설명은 대부분의 화면에서 **첫 150자만** 노출된다. 그래서 검색 키워드를 앞에 몰아넣는다.

### 2-3. 쇼츠 → 본편 유도 동선

현재 쇼츠에서 본편으로 가는 경로는 **설명란 1행 + 고정 댓글**뿐이다(실측: `refs/youtube-publish-log.md`). 쇼츠 시청자는 설명란을 잘 펼치지 않는다. 개선 3단:
1. **쇼츠 엔드카드 문구 교체** — 현재 `"전체 이야기는 채널에서"` + 구독 칩(실측: `video/build_shorts.py` `end_card()`). → `"전체 이야기 → 재생목록 '인터넷의 역사'"`로 바꿔 목적지를 명시한다. (4편부터 적용, 기존 6편은 재렌더가 필요하므로 보류)
2. **쇼츠 "관련 동영상" 링크** — 쇼츠에 본편을 공식 연결하는 기능. **API 지원 여부 미확인** → 결재 후 Studio에서 실측하고, 되면 6편 전부 지정한다.
3. **고정 댓글** — 문법은 `refs/community-strategy.md`에서 설계한다(중복 서술 금지).

## 3. 채널 홈 섹션 구성안

### 3-1. 무엇이 가능한지부터 (실측·조사)

- **`channelSections` API는 폐기되지 않았다.** list/insert/update/delete 4개 메서드 모두 유효(developers.google.com/youtube/v3/docs/channelSections, 2026-07-30 확인). 2021-05-12에 폐기된 것은 `style`·`defaultLanguage`·`localizations`·`targeting` **속성 일부**뿐이다.
- **채널당 섹션 상한**: API 문서 10개 / Studio 도움말 12개 — **문서 간 불일치**. 우리는 3개만 쓸 것이라 실무상 무관하지만, 숫자를 인용할 때는 이 불일치를 밝힌다.
- **API가 만들 수 있는 유형 10종**: `singlePlaylist`·`multiplePlaylists`·`allPlaylists`·`popularUploads`·`recentUploads`·`subscriptions`·`multipleChannels`·`liveEvents`·`upcomingEvents`·`completedEvents`
- **Studio가 제공하는 유형 8종**(support.google.com/youtube/answer/3027787): `For you`·`Videos`(동영상·Shorts·라이브를 필터로 고름)·`Playlists`·`Memberships`·`Channels`·`Top community clips`·`Effects`·`Posts`
- **⚠️ 두 목록이 일치하지 않는다.** Studio에만 있는 `For you`·`Top community clips`·`Effects`·`Posts`는 API `type` 값에 **없다**. 또 우리가 원하는 "쇼츠만 모은 줄"은 Studio의 `Videos` 섹션에서 **Shorts 필터를 고르는 방식**인데, API의 `recentUploads`에는 그런 필터 파라미터가 없다. → **API로 전부 처리하려 하면 2번 줄에서 막힌다.** [추정 — 두 공식 문서 대조에 의한 추론이며, 실제로 `channelSections.insert`를 시도해 봐야 확정]

### 3-2. 권고 배치 (위→아래)

| 줄 | 내용 | 이유 | 실행 경로 |
|---|---|---|---|
| 0 | **채널 트레일러**(비구독자용) | 구독자 4명 = 방문자 거의 전원이 비구독자. 이 슬롯이 사실상 유일하게 의미 있다 | 결재 항목 (라) |
| 1 | **재생목록 "인터넷의 역사"**(본편) | 쇼츠에서 넘어온 사람에게 **가장 먼저 팔 것**. 96.6%가 쇼츠 유입이므로 쇼츠를 또 보여줄 이유가 없다 | API `singlePlaylist` 가능 |
| 2 | **Shorts** | 익숙한 것으로 체류를 잇는다 | Studio 수동일 가능성 높음(API 유형 없음) |
| 3 | **최근 업로드** | 재방문자용 최신 확인 | API `recentUploads` 가능 |

**"인기 업로드" 줄은 권고하지 않는다.** 인기 상위 6개가 전부 쇼츠라 1줄·2줄과 내용이 겹치고, 본편(35회)을 화면 밖으로 더 밀어낸다.

### 3-3. 채널 트레일러 — 단정하지 않고 실험으로 (rule6)

어떤 영상을 트레일러로 걸어야 하는지는 **우리 데이터로 답이 안 나온다**. 본편 3편의 총 조회가 35회라 판단 근거가 없기 때문이다. 그래서 단정 대신 실험으로 처리한다.

- **가설**: 쇼츠 피드에서 넘어온 방문자에게는 "쇼츠와 같은 결"보다 **"본편 1편의 도입부"**가 구독 전환에 유리하다.
- **1차안**: 1편 본편 `aPR3TsM9Rls` (시리즈 시작점)
- **반증 데이터**: 1편 본편의 평균 시청 지속률은 **24.74%**(36초/149초, 2026-07-27 확정치) — 4명 중 3명이 36초에 이탈한다. 트레일러로 걸면 **첫인상이 이탈 장면**이 될 위험.
- **판정 기준**: 트레일러 지정 후 14일간 `구독자 증가수 ÷ 채널 페이지 조회수`를 지정 전 14일과 비교. **표본이 채널 조회 100회 미만이면 판정을 미룬다**(구독자 4명 규모에서 성급한 판정은 무의미).
- **대안(비용 발생 없음)**: 30초 전용 트레일러를 기존 컷 재활용으로 제작 → video-producer 반나절. 1차 실험 결과가 나쁘면 이 경로로 전환.

## 4. 업로드 절차 편입안

### 4-1. 자동 편입 (4편부터)

- 업로드 스크립트에 **`--playlist <id>` 옵션이 이미 존재**한다(실측: `~/.claude/skills/youtube-uploader/scripts/youtube-upload.ts` — 옵션 파싱 96행, `playlistItems.insert` 호출 337행).
- 필요한 스코프는 `youtube`이고 **업로더 토큰이 이미 보유**하고 있다(실측: 토큰 scope 문자열 = `youtube` + `youtube.upload`). → **재인증 불필요.**
- 편입안: 본편 업로드 시 `--playlist <A목록ID>`, 쇼츠 업로드 시 `--playlist <B목록ID>`를 발행 체크리스트 고정 항목으로 승격한다.

**⚠️ 실행 전 확인해야 할 결함 하나**: 위 스크립트의 재생목록 추가 코드는 실패해도 `console.error`만 찍고 **업로드 자체는 성공으로 끝난다**(349~351행). 즉 "편입 실패"가 조용히 지나갈 수 있다. → 발행 후 검증 단계에 **`playlistItems.list`로 실제 편입 여부를 왕복 대조**하는 1줄을 추가할 것을 권고한다(rule9의 왕복 검증 원리).

### 4-2. 소급 편입 (기존 9편)

- 기존 9편은 `playlistItems.insert`로 일괄 편입. API 가능, 추가 인증 불필요.
- **순서 주의**: 편입 순서 = 재생목록 표시 순서. 1편 → 2편 → 3편 순으로 넣는다.

## 5. 실행 계획 (결재 후)

| 단계 | 담당 | 경로 | 예상 | 검증 |
|---|---|---|---|---|
| ① 재생목록 A·B 생성 | publisher | **API**(`playlists.insert`, `youtube` 스코프 보유) | 2분 | 생성 후 `playlists.list`로 ID·제목·공개상태 재조회 |
| ② 기존 9편 편입 | publisher | **API**(`playlistItems.insert`) | 3분 | `playlistItems.list`로 항목 수·순서 전수 대조 |
| ③ 혼합 재생 동작 실측 | publisher | **API 생성 + 브라우저 관찰** | 10분 | 임시 목록에 본편1+쇼츠1 넣고 실제 재생 관찰 → 관찰 후 임시 목록 삭제 |
| ④ 채널 홈 섹션 배치 | release-director | **API 시도 → 실패 시 Studio 수동** | 10~15분 | 로그아웃 상태(또는 시크릿 창)에서 채널 홈을 열어 **시청자가 보는 화면**으로 확인 |
| ⑤ 채널 트레일러 지정 | release-director | **Studio 수동 권고** | 5분 | 시크릿 창에서 트레일러 자동재생 확인 |
| ⑥ 쇼츠 "관련 동영상" 링크 | release-director | **미확인 → Studio 실측 후 판단** | 15분 | 쇼츠 화면에 본편 링크 노출 확인 |
| ⑦ 업로드 체크리스트 개정 | publisher | 문서 | 5분 | 4편 발행 시 실사격 |

**API 가능 / UI 수동 구분 요약**
- **API로 확실히 되는 것**: 재생목록 생성·편입·순서, `singlePlaylist`·`recentUploads` 섹션
- **API로 안 되는 것(Studio 수동)**: Shorts 전용 줄, Posts 줄, For you 줄 [추정 — 유형 목록 대조]
- **미확인(실측 필요)**: 채널 트레일러의 API 설정(`brandingSettings.channel.unsubscribedTrailer`가 `youtube` 스코프로 쓰기 가능한지), 쇼츠 관련 동영상 링크

**어느 것도 새 권한을 요구하지 않는다** — 커뮤니티 전략 쪽에서 논의되는 `youtube.force-ssl` 재인증은 이 제안서의 실행에 **불필요**하다.
