🟢 한 줄 요약: 이레째(7일) 같은 문제 — 유튜브 접속 열쇠(OAuth 토큰)가 여전히 7/27 그대로라 오늘도 실측 데이터를 못 받았습니다.

## 문제점 (수집 실패, 실측 사실)

- 환경 문제(`_cffi_backend` 모듈 누락, 최근 며칠과 동일 증상) 재발 — 오늘도 `pip install cffi cryptography`로 우회 성공(오늘 조치 완료). 이건 매번 자동으로 고쳐지는 부분이라 본질적 문제는 아님.
- 실행: `YT_TOKEN_PATH=<yt-keys 경로>/youtube_oauth_token.json python video/fetch_analytics.py`
- 오류 원문(그대로 기록, 지어내지 않음):
  ```
  google.auth.exceptions.RefreshError: ('invalid_grant: Bad Request', {'error': 'invalid_grant', 'error_description': 'Bad Request'})
  ```
- 쉬운 설명: "OAuth 인증 토큰"은 우리 프로그램이 유튜브 데이터에 접근할 때 쓰는 "출입증"이다. 오늘도 구글은 "이 출입증은 유효하지 않다(invalid_grant)"고 거절했다 — 환경 문제(파이썬 라이브러리 충돌)는 오늘도 고쳤지만, 그것과 무관하게 출입증 자체가 여전히 만료·폐기 상태라는 뜻이다. 새 출입증(재로그인)이 필요하다는 결론은 변하지 않는다.
- 확인: `yt-keys` 저장소의 토큰 파일은 2026-07-27 커밋(`3868362`) 이후 변경 없음(오늘도 동일 확인, 토큰 자체 expiry 값도 2026-07-27 그대로) — 즉 아직 아무도 새로 로그인해서 출입증을 갱신하지 않았다.
- 새 snapshot/private JSON 파일 생성 안 됨(오늘자 실측 지표 0건 — 지표를 지어내지 않음).

## 문제점 (요약)

1. **[사실] OAuth 토큰 문제가 이레째(8/13→8/14→8/15→8/16→8/17→8/18→8/19) 미해결.** 데이터 공백이 8/3~8/19로 17일까지 늘어남.
2. **[사실] 재인증 조치가 아직 취해지지 않음.** `yt-keys` 저장소 토큰 파일이 7/27 이후 변경 없음 — 지난 엿새간 동일 보완점을 제시했으나 오늘도 조치되지 않았다.
3. **[추정] 방치 기간이 길어질수록 재인증 후에도 "전일 대비" 비교의 기준일이 계속 뒤로 밀린다.** 심층 지표(유지율 등)는 갱신이 늦어 재인증 직후에도 1~2일은 공백일 수 있음.

## 보완점

1. **[가장 시급, 이레째 반복] 사용자가 브라우저로 유튜브 OAuth 재인증을 진행해야 한다.** 새로 발급된 토큰(JSON)을 `yt-keys` 저장소의 `youtube_oauth_token.json`에 덮어써야 자동 수집이 재개된다. 이 작업은 브라우저 로그인이 필요해 자동화 루틴이 대신할 수 없다.
